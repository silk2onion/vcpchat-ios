# VCPChat iOS

连接你自己的 [VCPToolBox](https://github.com/lioensky/VCPToolBox)，在手机上与多个 Agent 聊天、查看工具审批和 RAG 信息流，并与桌面 VCPChat 同步历史。

客户端采用 **Tauri 2 + Vue 3 + TypeScript + Rust**。底栏是 **会话、通讯录、我**；桌面同步、文件、笔记和设置都放在“我”里。界面也可通过浏览器预览，或在 Mac 上运行原生开发版。

**先读这里：** 已安装 App 的用户从[首次连接](#first-chat)开始；想先试界面，看[本地演示](#development)；需要安装包，看[构建与安装](#ios)。下面描述的是当前源码功能，旧 IPA 不一定包含这些更新。

<a id="first-chat"></a>
## 首次连接与第一条消息

### 1. 填写服务器地址

打开 **我 → 设置 → 服务器与模型**：

1. **VCP 服务器 URL**：填写手机能访问的 ToolBox 地址，例如 `http://192.168.1.8:6005`。这里的地址和端口是示例，以你的服务器为准。
2. **API Key**：填写该聊天服务的密钥。
3. **接口**：普通 OpenAI 兼容服务选“OpenAI 兼容”；后端提供 VCP 专用路由时，选“VCP 工具模式”。
4. 点 **测试连接并刷新模型**，选择默认模型；也可以直接输入完整模型 ID。
5. 回到“会话”，打开默认助手，发送第一条消息。

**手机上的 `127.0.0.1` 指手机自己，不是 Mac。** 服务运行在电脑上时，应填写电脑的局域网地址或可达域名。日志、语音和桌面同步地址也遵循这个规则。

### 2. 两种接口模式怎么选

| 模式 | 发送聊天的路径 | 用法 |
| --- | --- | --- |
| OpenAI 兼容 | `/v1/chat/completions` | 连接实现该协议的模型服务 |
| VCP 工具模式 | `/v1/chatvcp/completions` | 连接提供此路由的 VCP 后端，由后端处理工具链 |

两种模式都使用 `/v1/models` 读取模型目录。URL 可以填主机地址、以 `/v1` 结尾的地址，或完整聊天路径；客户端会按所选模式整理路径。反向代理的前缀会保留，例如 `https://example.com/vcp`。

切换模式只改变请求路由，不会给普通模型服务自动增加 VCP 插件。手机负责发送消息和渲染返回内容；后端工具由后端执行。

### 3. 多个地址和密钥不要混用

| 用途 | 在哪里填 | 使用的凭据 |
| --- | --- | --- |
| 聊天、模型目录、服务器文件工具 | 设置 → 服务器与模型 | ToolBox API Key |
| VCPLog / VCPInfo | 设置 → 日志通道 | VCP WebSocket Key |
| 桌面历史同步 | 我 → 桌面同步 | 桌面 `MobileSyncToken` |
| 下载服务器原文件 | 文件 → 服务器文件 → 连接与目录设置 | `ImageFileServer` 的 `File_Key` |
| 服务器日记 | 设置 → 身份与日记 | 管理员用户名和密码 |
| TTS 服务 | 设置 → 语音与朗读 | 该语音服务自己的 Key；无鉴权 SoVITS 可留空 |

先连通聊天即可，其余功能按需配置；不必一开始填完所有字段。

<a id="agents-and-chats"></a>
## Agent、会话与群聊

### 创建和编辑 Agent

进入 **通讯录 → 右上角＋** 新建 Agent；编辑已有 Agent 时，点它右侧的菜单，也可以在聊天顶部点头像打开资料。

可配置：

- 图片头像、文字头像、名字和简介。点头像选择 JPG / PNG / WebP / GIF，原始头像文件上限 5MB；也可选内置 VChat 头像。
- **系统提示**：角色、语气、任务和工作方式。保存后用于后续请求，不会重写已保存的回复。
- **模型**：可指定完整 ID，留空继承全局默认模型。
- **Temperature**：0–2，留空继承全局值；只有全局“发送 Temperature”开启时才随请求发送。
- **这个 Agent 的声音**：音色、语速、导演提示词；未填写的项继承全局设置。MiMo 的语速和情绪用导演提示词控制。
- **Agent 正则**：专属于这个 Agent 的显示或上下文规则。

会话页顶部固定主 Agent。通过“更换主 Agent”或 Agent 资料里的“设为主 Agent”更换固定入口；旧 Agent 和历史不会移动或删除。

App 中的 Agent 是聊天资料，不等于 ToolBox 后端 `Agent/*.txt` 或 AgentAssistant 注册项。当前可以手动编辑，也可以同步桌面资料；尚不能在聊天里让 Agent 直接修改手机设置。

### 使用多个话题

- 从“会话”的＋选择 Agent 或群组，新建话题。
- 聊天顶部的历史按钮切换该 Agent / 群组的话题；菜单可重命名或删除话题。
- 草稿和待发送附件按话题分别保留。生成中切到其他话题，不会因为页面切换而取消原来的回复。
- 点停止按钮可停止生成。传输中断后，已收到的正文保留；最后一条中断回复可点 **继续写**，由原来的 Agent 续写到同一气泡。

原生壳由 Rust 持有聊天流，并保存分段以供界面补齐；浏览器预览使用页面里的流式请求。iOS 后台执行时间由系统决定；应用完全退出后不能保证连接继续，重开时未完成回复会按中断处理。

### 群聊发言方式

在通讯录的群聊区域新建群聊，选择成员和发言方式：

- **@点名，否则轮流**：点名时被点到的成员回复，否则轮到一位成员。
- **轮流一位**：无点名时轮流选择一位。
- **随机发言**：无点名时随机选择一位。
- **仅点名发言**：没有点名就不产生 Agent 回复。
- **每位依次回复**：无点名时成员依次回复，不是并行生成。

用 `@完整名字` 点名，名字后接空格、标点或消息结尾。当前实现中，明确点名优先于上述默认策略。桌面同步群组若启用了统一模型，群组统一模型优先于成员模型。

### 模型超过 300 个时

点模型输入框旁的箭头打开选择器，用关键词过滤；例如 `qwen coder` 会同时匹配两个词，不区分大小写。方向键和 Enter 可选中，Escape 关闭。完整模型 ID 不会被截短后保存。

目录缓存在本机，设置与 Agent 编辑共用缓存，切页和重开不必重新等待服务器。候选列表只挂载可视行及少量预加载行。更换服务器或聊天 Key 会清除旧目录；需要更新时手动刷新，刷新失败不会清掉当前连接的已有缓存。

### 输入与附件

**我 → 设置 → Enter 发送消息**：

- 默认关闭：Enter 换行，⌘/Ctrl+Enter 发送。
- 开启：Enter 发送，Shift+Enter 换行；⌘/Ctrl+Enter 仍可发送。
- 中文输入法选字期间不会用 Enter 误发送。

聊天输入栏的＋接收图片或文本，单条消息最多 4 个附件：图片每个最多 1,500,000 字节，文本每个最多 200,000 字节，不接收 SVG。历史中的附件继续显示，但请求只附带当前上下文里最后一条用户消息的附件内容；图片还需要所选模型支持视觉输入。

每次请求最多选取最近 **32 条会话记录**，再附上系统提示；这是发送上下文窗口，不是历史保存上限。旧消息仍保存在本机。

<a id="rendering"></a>
## 消息渲染、外观与性能

### 看代码、公式、工具和 HTML

- Markdown：标题、列表、表格、链接和代码块；代码可复制。
- 数学公式：`$…$`、`$$…$$`、`\(…\)`、`\[…\]`；普通价格 `$5` 不当作公式。
- Mermaid：完成后的图表代码按需渲染。
- 思考内容：支持独立 `reasoning_content` 和 `<think>` 思考块。
- VCP 工具：`TOOL_REQUEST`、结果汇总、状态和返回内容；代码围栏里的工具标记保持为代码，不当成真实调用。
- 日记：`DailyNote` create / update、旧版日记标记；创建显示卡片，更新显示“原文 → 改为”。
- HTML：整页 HTML 或带 `<style>` / `<script>` 的片段在独立 iframe 中运行；HTML 代码块可打开预览。CSS 动画、Canvas 和页面自带的脚本可在气泡中运行。

HTML iframe 与 App 的 DOM、IndexedDB、Cookie 和 Tauri 接口隔离。它不能发起 fetch / XHR / WebSocket，也不能提交表单或嵌套 iframe；HTTPS 脚本、样式以及允许来源的图片、媒体仍可加载，所以不等于完全断网。需要远端库的 HTML 在离线时可能无法完整显示。

### 调整外观和省电渲染

**我 → 设置 → 外观** 可选墨色、纸色、极光；壁纸可选林间夜游、雨后绿叶、无壁纸或自选图片，并调整遮罩和模糊。自选壁纸原文件上限 8MB，支持 JPG / PNG / WebP / GIF；图片保存在本机，不依赖旧构建的资源地址。

**我 → 设置 → 高级渲染** 提供总开关，以及代码高亮、公式、Mermaid、HTML、图片视频和动画子开关。关闭总开关保留轻量 Markdown；切换后已有消息立即按新设置重新渲染。页面、弹层与通知抽屉有进出动画，并跟随系统“减弱动态效果”。

### 长对话怎样处理

流式内容照常接收和保存，界面每个屏幕帧最多更新一次。高亮、公式和图表等增强处理，会等待流式结束且内容接近可视区时再进行。

**聊天消息列表目前不是完整的虚拟列表**：已有消息仍会挂载到页面。不要把“富渲染按需增强”理解成“只有屏幕里的消息才存在”。模型选择列表的可视窗口优化是另一项实现。

## 语音与朗读

### 连接 SoVITS

1. 打开 **我 → 设置 → 语音与朗读**，选择“**SoVITS · VChat 兼容**”。
2. 服务地址填写基础地址，例如 `http://192.168.1.8:8000`，不要填完整语音路径。
3. 若服务启用鉴权，填写它的 API Key；无鉴权可留空。
4. 点“刷新音色”，选择音色 ID，调整语速，再点“试听这段声音”。
5. 回到聊天，点回复下方的扬声器朗读。

适配的是 VChat 的 **v2ProPlus** 契约：`POST /models` 携带 `version: v2ProPlus`；`POST /v1/audio/speech` 携带 `model: tts-v2ProPlus`。不是任意名称为 GPT-SoVITS 的服务都能直接兼容。

### 连接 MiMo

选择“**MiMo · 网络语音**”，填写服务提供方的地址、API Key、模型与音色。地址可填以 `/v1` 结尾的基础地址，或完整 `/chat/completions` 路径；客户端会补齐缺少的聊天路径。

“刷新音色”显示客户端内置的 MiMo 候选，并不是请求服务端模型列表。自然语言导演音色需要填写导演提示词，例如“轻声、自然地说，语速稍慢”；实际模型和音色可用性以你的服务为准。该适配器接收 SSE 中的 PCM16 音频，按 24kHz 单声道播放。

### 朗读操作

回复下方的扬声器开始朗读；迷你播放器可暂停、继续和停止，并显示进度。朗读提取正文，不念工具参数、代码块或隐藏思考；长文本会分段合成。

当前是**手动朗读**，没有收到回复即自动播放、语音输入或语音唤醒。Agent 的声音设置可覆盖全局值；桌面本地克隆音色文件不随历史同步传输。

## 正则规则

想把回复中的某个称呼换掉，可以先在 **我 → 设置 → 全局正则** 新建规则：

1. 填规则名称，如“替换称呼”。
2. 查找表达式填 `/助手/g`，替换为 `Amadeus`。
3. 角色选择“Agent”，作用范围选择“显示的消息”。
4. 在“试一试”里输入样本文字，确认结果后保存。

规则支持新建、编辑、排序、启停、试替换、VChat / SillyTavern JSON 导入和单条导出；导入文件上限 500KB。Agent 资料里也能设置专属规则，执行顺序为**全局规则 → Agent 规则**。

两种作用范围相互独立：

- **显示的消息**：只改变看到的画面。
- **发给模型的上下文**：只改变发出的副本。

保存的原始消息不变。可按用户 / Agent 角色和回合深度筛选；0 是最近一轮，-1 为不限。修改显示规则后可查看已有消息的新效果。

<a id="activity"></a>
## 通知、工具审批、VCPLog 与 RAG

### 连接两个信息通道

打开 **我 → 设置 → 日志通道**，填写 VCP WebSocket URL，例如 `ws://192.168.1.8:6005`，以及服务器配置的 WebSocket Key，然后点“连接日志通道”。

客户端分别建立：

- VCPLog：`/VCPlog/VCP_Key=<key>?deviceName=VCPChat-iOS`
- VCPInfo：`/vcpinfo/VCP_Key=<key>`

HTTP / HTTPS 地址也会转换成对应 WS / WSS 地址。反向代理需要正确转发 WebSocket 升级和这两条路径。连接失败按退避重连；回前台会恢复连接，后台超过 20 秒的旧连接会主动重建。

点聊天右上角的铃铛，或 **我 → 通知中心**，可在“通知 / VCPLog / RAG 监视器”之间切换，不用离开当前会话。通知角标提示新事件和待处理审批。

### 处理工具审批

服务器发送兼容的工具审批事件后，卡片显示 Agent、工具、参数与变更预览。可填写原因，选择允许一次或拒绝。

“**已发送 · 等待确认**”表示客户端已发出决定；收到服务端回执后才显示“已允许 / 已拒绝”。断线时不发送，也不会重连后自动重发审批；清空诊断日志会保留尚未完成的审批。它与桌面 `WaitingForUrReply` 插件的任意弹窗不是同一条接口。

### 查看 RAG 与其他事件

RAG 监视器显示检索问题、知识片段、来源、分数、标签和检索方式；也识别元思考、Agent 私聊、记忆检索和梦境等事件。原始 JSON 可展开查看或复制。它展示服务端已发来的事件，不会自己执行一次 RAG 检索。

单条事件上限 2MB；超出时显示错误，不把截断 JSON 当成正常记录。诊断日志通常保留最近 200 条，未完成审批另行保留；这不是服务器完整日志归档。

<a id="sync"></a>
## 与桌面同步

同步对象是 **桌面 VCPChat 的联系人、群组、话题、消息和头像**，不是 ToolBox 后端 `Agent/*.txt`，也不是手机全量系统备份。协议固定为 **Wire 1.5**。

### 1. 准备桌面端

桌面端需要包含 [VCPMobileSync 插件](https://github.com/lioensky/VCPChat/tree/1fadcf1531151cd7c5070fc1737d944133918dba/VCPDistributedServer/Plugin/VCPMobileSync)。按上游说明安装对应依赖，并从插件的 `config.env.example` 创建 `config.env`：

```env
MobileSyncToken=替换为你自己的同步令牌
MobileSyncPort=5975
```

在桌面 VCPChat 的全局设置／高级功能中开启“VCP 分布式服务器”，重启后确认服务就绪。使用中央索引 CDS 的桌面版本还需等待 CDS 启动成功；不要因错误而直接改库或删除历史。

手机与电脑需要网络互通，例如同一局域网或同一私有组网。同步端口使用 Token 鉴权，建议在私有网络中使用。

### 2. 第一次从桌面拉取

打开 **我 → 桌面同步**：

| 字段 | 示例 | 指向什么 |
| --- | --- | --- |
| 桌面 HTTP 地址 | `http://192.168.1.8:5974` | 桌面分布式服务的 HTTP 端口，默认 5974，不是 ToolBox 聊天端口 |
| 同步 WebSocket 地址 | `ws://192.168.1.8:5975/` | `MobileSyncPort`，也可用 `/ws-sync` 路径 |
| Mobile Sync Token | 自己配置的令牌 | 与桌面插件的 `MobileSyncToken` 一致 |

HTTP 地址也可包含末尾 `/api/mobile-sync`。选择“**从桌面拉取**”，点“开始同步”，等待“同步完成”及条目统计。

导入内容使用独立来源身份；即使桌面和本机都有 `agent_default` 或同名话题，也不会盖掉旧本机记录，不会把不同 Agent 的同原始 ID 话题混在一起。原来的主 Agent 入口保留。

### 3. 双向写回与日常使用

在导入的 Agent 中继续聊天、新建话题、修改资料或删除同步项后，选择“**双向同步**”再开始。它会把这个来源的改动和删除写回桌面；原有或新建的本机 Agent 不会自动加入来源或上传。

- 当前为**前台手动同步**。聊天还在生成时不能开始；切到后台会取消未完成同步。
- 单向拉取发现本机未同步改动会停止，提示改用双向同步，不直接覆盖。
- 手机可编辑并回写名字、系统提示、模型、Temperature 和 Agent 图片头像。手机扩展的简介、音色和正则留在本机。
- 同步会保留未知桌面配置字段；保留字段不表示手机已实现该桌面功能。桌面群组的提示词和启用的统一模型可用于手机后续对话。
- 手机本地身份、连接设置和密钥不被桌面资料覆盖；桌面用户头像仅保存在同步元数据中。

本机内容只在最终确认后原子保存；提交前还会检查本机是否有并发编辑。双向远端操作逐项生效，断线前已被桌面确认的写入可能已经完成；解决错误后可手动重试对齐。

### 4. 恢复本机与取回附件

每次成功同步保存一个本机恢复点。点“**恢复到上次同步前**”并确认，仅恢复这个来源的本机内容；同步后在该来源新增的本机改动会被替换，其他来源和旧本机会话不动。恢复点消费后，需下一次成功同步才会生成新恢复点。**它不撤销桌面已经完成的写入。**

历史附件同步的是名称、类型、内容 hash 和可用提取文本，不包含原文件字节。文件库已有相同内容时自动关联；否则消息显示“桌面附件未下载”。到“我 → 文件”导入原件，或从服务器下载原文件，相同内容会关联到同步附件；不必删除或重建消息。

原库协议、版本和接口依据见 [原库同步与文件调查](docs/UPSTREAM_SYNC_AND_FILES.md)。

## 本机与服务器文件

### 本机附件：导入、预览和带走原文件

进入 **我 → 文件 → 本机附件**：

1. 点“导入文件”选择文件；或者点“收集已有聊天附件”，把已有可用聊天附件收集为文件库副本。
2. 点文件预览。文本和常见图片可在页面查看；其他类型保留原字节，可导出后用系统应用打开。
3. 点“导出原文件副本”。同名文件会另存为带序号的副本，不覆盖前一次导出。
4. “从本机文件库移除”只移除文件库项目，不删除聊天历史中的内容。

文件按实际内容去重，重复导入相同字节不会增加副本，沿用第一次登记的文件名；本机库单个文件上限 20,000,000 字节。导入本机库不会自动上传到服务器，也不会自动作为下一条聊天附件发送。聊天输入栏的格式与大小限制仍单独适用。

导出位置：

- **Mac**：点“查看导出位置”打开 Finder。默认应用标识下位于 `~/Library/Application Support/app.vcpchat.ios/VCPChat Exports/`；不同构建标识使用各自目录。
- **iOS**：构建已配置文件共享，可在“文件 → 我的 iPhone → VCPChat → VCPChat Exports”查找导出副本。这条路径尚待本轮新版真机验证。
- **浏览器**：交给浏览器的下载功能处理。

### 服务器文件：先选择浏览起点

1. 先在“服务器与模型”填写 ToolBox URL 和 API Key。
2. 进入 **文件 → 服务器文件 → 连接与目录设置**。
3. 文件工具默认名为 `ServerFileOperator`，对应 ToolBox 的 `FileOperator` 插件；自定义过名称则按实际配置填写。
4. 点“读取服务端允许目录”选择起点，或填一个服务器绝对路径，例如 `/home/user/VCPToolBox/file` 或 `C:/VCPToolBox/file`。
5. 收起设置，点目录输入框旁的刷新按钮读取列表。

这些路径指服务器，不是手机。浏览起点约束本页的导航范围，实际读写权限由服务器决定，不应把它当成服务器的完整权限隔离。

### 浏览、上传与管理

点文件夹进入，点“上一级”返回；空目录也能上传或新建。文件夹右侧菜单可打开管理操作。

- **上传文件**：单次上限 10,000,000 字节；已有同名文件保留，由服务端另存新名称。
- **新建**：创建文本文件或文件夹。文本内容会以文件形式上传。
- **读取内容 / 文档提取**：文本直接读取；支持的图片显示预览；其他文档可能返回提取文本。支持类型取决于服务端 FileOperator。
- **重命名 / 移动**：填写目标绝对路径并确认；目标已存在时不覆盖。
- **复制**：仅文件支持，已有同名文件由服务端另存副本。
- **移入服务器回收站**：确认后调用原版删除工具，实际回收站支持取决于服务器环境。

按钮直接调用 `/v1/human/tool`，不经过聊天模型。返回成功后刷新目录；服务器拒绝、断线或工具错误会显示在页面。

### 下载的是原文件，还是提取文本？

“读取内容”不等于下载原文件。需要 PDF、音频、压缩包等原件时，点“**下载原文件到本机**”。这走 `ImageFileServer` 的文件分发接口，还需设置：

- **File Key**：服务器 `ImageFileServer` 配置中的 `File_Key`。
- **服务端 file/ 目录的绝对路径**：对应分发目录，例如 `/home/user/VCPToolBox/file`。

客户端按该映射请求 `/pw=<File_Key>/files/<相对路径>`；只支持分发目录内、服务端允许分发的原文件，单个下载上限 20MB。目录外文件可以先读取提取内容，或复制进分发目录再下载。下载后在“本机附件”中查看或导出。

**我 → 笔记 → 本机** 可新建、编辑、保存或删除笔记，不需要网络。退出编辑前点“保存到本机”；正文不是输入即自动保存。

<a id="data"></a>
## 数据保存、更新与恢复

会话、Agent、群组、笔记、配置和文件库存于当前设备的 IndexedDB。密钥也存于本机 IndexedDB，当前未接系统钥匙串。没有内置公共云账号，也没有一键导出／导入全部 App 数据的入口。

- 发送聊天时，所选上下文和本次附件会发给配置的聊天服务器；TTS、日记、文件与同步只在使用对应功能时请求各自服务。
- 浏览器、不同网站地址、开发预览、Mac App 和 iPhone 各自有存储环境，不会因打开同一仓库就共享数据。
- 本机文件导出不是聊天整库备份；桌面同步也只覆盖指定来源，不替代全部本机数据备份。

### 更新已有安装

当前默认 Bundle ID 为 `app.vcpchat.ios`。更新时沿用原有应用身份和数据容器，不要先卸载再安装；卸载或清除网站数据可能使本机记录丢失。修改 Bundle ID 会成为另一份独立安装，旧记录不会自动搬过去。

数据库目前为**版本 2**：在旧表上增加文件表与同步元数据，不清空旧会话、头像、笔记和设置。旧版只认识版本 1 时，直接回退可能出现数据库版本错误；需要兼容版本 2 的构建或专门的数据迁移，不能靠删除数据库“修复”。

“恢复到上次同步前”只作用于那个同步来源，不是整个 App 的撤销按钮，也不影响服务器文件操作。服务器上的复制、移动、改名、日记保存和同步写回，按各自操作结果生效。

然后在 App / 网页中填写：

### Mac 环境要求

- **完整版 Xcode 16 或更新**，不是只有 Command Line Tools；在 Xcode 的 Settings → Components / Platforms 中装好 iOS 平台和所需模拟器。
- Node.js 22、pnpm 10、rustup；Rust 固定 1.99.1。
- 当前项目最低系统版本配置为 **iOS 16.0**；这不表示已对每个 iOS 版本逐一实测。

先确认开发目录和版本：

```bash
sudo xcode-select -s /Applications/Xcode.app/Contents/Developer
xcodebuild -version
xcodebuild -showsdks
```

首次启动 Xcode 时按提示完成组件准备。然后在项目目录执行：

```bash
pnpm install
pnpm check
cargo test --lib --manifest-path src-tauri/Cargo.toml --locked

# 集中存放本次构建的临时文件
archive="$HOME/CodexArtifacts/vcpchat-build-$(date -u +%Y%m%dT%H%M%SZ)"
mkdir -p "$archive/tmp"
export TMPDIR="$archive/tmp/"

# 构建模拟器 App
bash scripts/build-ios-simulator.sh

# 构建未签名设备 IPA

```

两个脚本都会按需执行 `tauri ios init`、安装目标并应用 plist 补丁，不必每次手动初始化。它们使用 `--locked`；若提示锁文件需要变化，先检查依赖与工具链差异，不要为绕过错误直接删锁文件。

产物：

- **设备 IPA**：`dist-ios/VCPChat-unsigned.ipa`，未签名，需要重签后安装。
- **模拟器 App**：位于 `src-tauri/gen/apple` 的构建目录；当前 workflow 使用 `src-tauri/gen/apple/build/arm64-sim/VCPChat.app`。
- 模拟器脚本目标为 `aarch64-sim`，供 Apple Silicon 模拟器使用，不能当作 Intel 模拟器包或真机包安装。

plist 补丁加入本地网络访问说明、HTTP 传输配置、相册说明和文件共享设置。它不会赋予任意系统文件访问权限。

若已安装 fastlane，也可在仓库根目录运行 `fastlane ios unsigned` 或 `fastlane ios simulator`，实际调用同一组脚本。

### 安装到模拟器

在 Xcode 中启动匹配架构的 iPhone 模拟器，将生成的 `.app` 拖入；或使用：

```bash
xcrun simctl install booted src-tauri/gen/apple/build/arm64-sim/VCPChat.app
xcrun simctl launch booted app.vcpchat.ios
```

应用路径按本次实际输出调整。模拟器用 `.app`；未签名设备 IPA 不能代替模拟器包。

### 签名并安装到 iPhone

选择一种方式即可：

- **AltStore Classic**：先按 [AltStore 官方说明](https://faq.altstore.io/) 配好电脑端 AltServer 和手机端 AltStore，再在手机的 My Apps 中导入 IPA；之后按签名有效期刷新。
- **Sideloadly**：用数据线连接并信任电脑，把 IPA 拖入 [Sideloadly](https://sideloadly.io/)，选择设备、填写自己的 Apple ID 后签名安装。
- **Xcode**：打开 `src-tauri/gen/apple/*.xcodeproj`，选择实际生成的 App target，在 Signing & Capabilities 选择自己的 Team，选择真机后运行。以生成项目的 target 名称为准。

按设备提示完成开发者信任或开发者模式设置。已有安装更新时，尽量沿用原来的签名身份与 Bundle ID；改成新的 Bundle ID 会产生独立数据容器。不要用卸载 App 来处理签名刷新问题。

### 在 GitHub Actions 构建

仓库有手动触发的 [iOS workflow](.github/workflows/ios.yml)：

1. 推送需要构建的代码，在 GitHub 的 Actions 中选择“iOS”。
2. 点“Run workflow”，选对应分支。正常构建保留 `run_checks` 开启。
3. 等待检查、模拟器构建、未签名 IPA 构建和模拟器启动检查结束。
4. 从 run 的 Artifacts 下载 `VCPChat-iOS-products`；失败时下载 `VCPChat-iOS-logs` 查看完整日志。

当前 workflow 使用 `macos-15`，产物含模拟器 `.app.zip` 和未签名 IPA；日志与产物保留 14 天。它没有签名证书，也不会自动安装到你的 iPhone。普通 push / PR 不会自行触发该打包流程。

<a id="faq"></a>
## 常见问题

### 网页能连，iPhone 连不上

先确认手机没有用电脑的 `127.0.0.1`。检查手机到服务器的网络、监听地址、端口与本地网络权限；网页页面能打开，不等于后端接口可达。HTTPS 页面直连 HTTP 服务还可能受到浏览器限制。

### 模型目录为空或测试连接失败

检查聊天 API Key、URL 和 `/v1/models` 是否存在。部分服务没有模型目录，可手动填写模型 ID，但仍需验证聊天路由。模型报参数错误时，先关闭“发送 Temperature”；工具路由 404 则核对服务是否支持 `/v1/chatvcp/completions`。

### 为什么桌面同步连接失败，或者显示 CDS 错误

聊天端口、桌面分布式 HTTP 端口、同步 WebSocket 端口是不同服务。核对 5974 / 5975 是否被改过、Token 是否一致、分布式服务器是否启动。若桌面报告 CDS 未就绪，先查看桌面日志解决服务启动问题；客户端不会自动把 CDS 错误改成另一套数据源。

### 为什么拉取提示“本机有改动”

这是避免覆盖的保护。需要保留并写回这些改动时，选择双向同步；要恢复到先前状态时，先确认恢复点的影响范围。不要删除本机历史来强行重新导入。

### 为什么服务器文件能读，原文件却下载不了

文档提取和原文件分发是两条接口。检查 `File_Key`、`file/` 目录映射和服务端允许分发的文件类型。目录外或被服务端禁止的类型不能直接下载；HTTP 403 也可能是分发规则拒绝，不一定是聊天 Key 错误。

### 为什么 RAG 页空白，或者审批没有结果

先分别检查 VCPLog、VCPInfo 的连接状态，再确认服务端确实发出了对应结构事件。普通日志文本不会自动变成 RAG 数据；没有待审批事件就没有审批卡。审批显示“已发送”仍需等服务端回执，不能当作已执行。

### 为什么 HTML 动画或脚本没显示

检查“高级渲染”总开关和 HTML 子开关，HTML 代码块需要点预览。iframe 不允许访问 App 或使用 fetch / WebSocket；外部脚本加载失败也会影响动画。普通 Markdown 中的代码示例不会被当作工具执行。

### 后台一分钟后回复一定继续吗

不保证。iOS 决定后台执行窗口；原生缓存可补齐仍存活的流，确实断开的回复保留已写内容并显示中断，再用“继续写”。桌面历史同步则是前台任务，后台会取消；它不是 APNs 推送或后台常驻节点。

### 能不能让 Agent 或外部程序直接改头像、提示词和设置

目前只能手动编辑，或从桌面同步支持的资料。手机没有 AppControl、对外配置 HTTP 接口或分布式执行工具。外部控制、离线请求队列和自动授权仍是方案，不能把工具卡片渲染当作手机已经执行了配置修改。

### 原生壳里某些旧确认按钮点了没反应

清空日志、清除历史／密钥、删除正则等旧入口仍使用浏览器 `confirm`；原生壳中确认可能不弹出。这些入口的统一确认替换尚未完成。新文件管理和同步恢复已使用 App 内确认面板。

“清除密钥”的当前处理范围是聊天 Key、日志 Key、管理员密码与 TTS Key；同步 Token 和 File Key 需在各自页面单独清空。

### 是否有完整备份、自动云同步或任意插件运行能力

没有一键整库备份和公共云同步。已有的是指定桌面来源的前台同步、本机文件导出和服务器文件工具；不能用桌面 Node / Shell 插件直接在手机运行，也不能在 HTML 气泡里获取 Tauri 权限。

<a id="architecture"></a>
## 代码结构、上游与许可

```text
src/
├── views/          # 会话、通讯录、我、设置、同步、文件、笔记
├── components/     # Agent 编辑、模型选择、消息、通知与确认面板
├── stores/         # 会话、设置、日志、语音与同步状态
├── protocol/       # 聊天 / SSE、工具、日记、端点、语音与正则
├── render/         # Markdown 增强、HTML iframe、逐帧显示
├── sync/           # Wire 1.5、DTO 投影、来源身份、原库契约
├── files/          # 本机文件库、文件工具和二进制传输
└── storage/        # IndexedDB、内存实现和原子同步提交
src-tauri/src/      # 原生网络、聊天流、后台任务、iOS WebView、文件导出
scripts/            # Mock、iOS 构建、plist 补丁和模拟器检查
```

Vue 负责界面，TypeScript 负责领域与协议、存储适配，Rust 提供原生网络、聊天流、后台时间申请与导出能力。网页预览和原生壳共用前端，但传输与平台能力不同；例如 MobileSync 控制面使用前端 WebSocket，不能笼统理解为所有连接都由 Rust 执行。
